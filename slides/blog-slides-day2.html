STEP 15🖱 내가 직접SQL Editor

글쓰기 권한 열기

지금 DB는 읽기만 허용됨. 저장하려면 쓰기 권한과 규칙을 추가함

SQL Editor → Run
-- 방문자(anon)가 글을 추가할 수 있게 허용
grant insert on public.posts to anon;

-- 누구나 쓰되, 길이는 제한함
create policy "public can insert posts"
on public.posts
for insert to anon
with check (
  char_length(title) between 1 and 100
  and char_length(content) between 1 and 5000
  and char_length(author) between 1 and 30
);
🚪
지금 설정은 "누구나 글을 쓸 수 있음"
수업용으로 단순하게 열어둔 것. 주소를 아는 사람은 누구나 쓸 수 있음
🔐
실제 서비스는 로그인한 사람만 쓰게 해야 함. 로그인(인증)은 이 수업 범위 밖임
📏
길이 제한(with check)은 최소한의 방어일 뿐임

STEP 17💬 에이전트에게

배포 전 보안 점검

깃허브에 올리면 코드가 공개됨. 올리기 전에 점검함

✓.env 파일이 git 추적 대상 아님
✓소스에 sb_secret_ · service_role 없음
✓URL · 키 값이 코드에 직접 없음
✓.gitignore 에 .env.local 있음
claude · 점검만 함
지금부터 점검만 하고, 파일은 절대 수정하지 마.

1. .env 로 시작하는 파일이 git 추적 대상인지
2. src·설정 파일에 sb_secret_ 또는
   service_role 문자열이 있는지
3. 소스에 URL·키 값이 직접 적혀 있는지
4. .gitignore 에 .env.local 이 있는지

결과를 표로, 문제 항목만 따로 알려줘.
🚨
비밀 키가 이미 올라갔다면 파일에서 지우는 것만으로는 안전해지지 않음. 그 키는 즉시 폐기하고 새로 발급받음 (Supabase 대시보드의 API Keys). 하나라도 문제면 배포하지 않음
