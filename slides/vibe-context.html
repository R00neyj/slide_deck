4. 길어진다고 똑똑해지지 않음

중간이 먼저 묻히고, 가득 차기 전에 나빠짐

lost in the middle*

긴 입력에서 앞뒤보다 중간에 있는 정보를 모델이 잘 놓치는 현상

* Liu et al., 2024 (arxiv.org/abs/2307.03172)

실무 활용 팁

내일부터 바로 쓰는 습관

  1. 요청할 때 목표 + 제약 + 검증 방법 세 가지를 같이 적기
  2. 에러는 전체가 아니라 마지막 부분 + 언제부터인지 한 줄
  3. 중요한 결정은 말로 끝내지 말고 파일에 남기기
  4. 주제가 바뀌면 새 세션. 작업 하나 = 세션 하나
  1. 일단락되면 비우고, 길어지면 쪼개거나 나눠 맡기기. 자동 압축(약 967K)을 기다리지 말기
  2. 오래 쉬었다 돌아오면 결정 사항을 파일에 남기고 /clear 후 이어가기 (캐시 만료로 첫 요청이 비쌈)
  3. 가끔 /usage로 토큰 사용량과 캐시 상태 확인
  4. 사외 AI 도구에는 민감 정보를 지운 재구성 내용을 줄 것

MCP와 Skill은 상주 비용이 다름

MCP를 붙이면 상주 비용이 늘 수 있음서버의 도구 정의가 전부 상주하면 부담이 큼. 예전 자료에서는 GitHub + Slack + Jira를 붙이면 약 72K(200K의 36%)가 찬다고 했음. 1M 기준으로는 약 7%. 안 쓰는 서버는 빼는 게 기본
최신 하네스는 도구 이름만 올려둠 (Tool Search)상세 내용은 필요할 때 불러옴. Claude Code는 기본값이 이 방식
Skill은 단계적 공개라서 훨씬 쌈평소에는 제목 · 설명 몇 줄(스킬당 약 50토큰)만 상주하고, 관련 작업이 감지될 때만 본문(약 2K)을 읽음. 전부 상주하는 지침 파일과의 차이
MCP 직결 vs CLI + Skill같은 GitHub 작업이 약 18K 상주 vs 약 50토큰 상주. 안 쓰는 날 차이는 약 300배. 원격 서비스 인증, 터미널 불가 환경, 다중 사용자 권한 · 감사 기록이 필요하면 MCP가 맞음

API 수준에는 오래된 도구 결과를 자동 삭제하는 기능(context editing)도 있음

출처: Claude Code Docs · 컨텍스트 창 (code.claude.com/docs/en/context-window), "full schemas stay deferred and Claude loads specific ones on demand via tool search"

정리

다섯 가지만 기억

  1. 책상에 없으면 AI에게는 없는 것임. 필요한 정보는 책상에 올릴 것
  2. 책상은 1M으로 커졌지만 유한하고, 시작부터 상주 비용(예시 27K)은 이미 차 있음
  3. 모든 행동에는 토큰 가격이 있음. 파일 읽기, 로그, 왕복 전부
  4. 단가는 그대로지만 매 요청마다 전체를 다시 읽음. 캐시가 크게 줄여주지만 쉬면 만료됨
  5. 길어지기 전에, 일단락되면 비우거나(/clear · /compact), 쪼개거나, 나눠 맡길 것(서브에이전트)

주석 및 용어 설명

컨텍스트(context window)AI가 지금 참고하는 내용 전체가 담기는 한정된 공간. 최신 Claude 모델 대부분은 1M 토큰
토큰AI가 글을 세는 단위. 글자 조각 하나 정도
상주 비용매 턴 자동으로 자리를 차지하는 부분. 시스템 지시, 도구 정의, 지침 파일
하네스(harness)모델을 감싸 도구 실행 · 컨텍스트 관리를 해주는 프로그램 (Claude Code 등)
에이전트 루프목표 이해 → 정보 확인 → 도구 호출 → 결과 추가 → 검증을 반복하는 동작 방식
자동 압축(compaction)책상이 차면 과거 대화를 요약문으로 갈아끼우는 것. 복원 불가
/compact대화를 요약본으로 교체하는 명령
/clear책상을 비우고 새로 시작하는 명령
context rot컨텍스트가 길어질수록 성능이 흔들리는 현상
lost in the middle긴 입력에서 중간에 있는 정보를 놓치는 현상

서브에이전트별도의 책상을 받아 일부 작업을 대신하는 AI 작업자
RAG외부 문서에서 관련 부분만 검색해 컨텍스트에 넣는 방식
MCP외부 도구 · 데이터를 AI에 연결하는 공개 표준
Agent Skill절차와 도구 사용법을 파일로 묶어둔 확장. 필요할 때만 로드됨
단계적 공개(progressive disclosure)제목만 들고 있다가 필요한 장만 펴 보는 방식
캐시(prompt cache)이미 처리한 앞부분을 잠시 저장해 두고 다음 요청에서 싸게 재사용하는 장치
TTL캐시가 유지되는 시간. 지나면 만료되어 다시 전체를 처리해야 함
사용 한도구독 플랜에서 일정 시간 동안 쓸 수 있는 사용량. 책상이 길수록 빨리 닳음
